WT Translator Local — настольный редактор **русской колонки локализации** War Thunder.
Найдите строку по русскому тексту, английскому тексту или ключу, сохраните свой вариант
в патч и примените его к папке `lang`.

Правки хранятся отдельно от файлов игры в JSON-профилях. После обновления игры можно
получить свежую локализацию и повторно применить свой патч. Приложение работает
локально, без аккаунта, серверной части и облачной синхронизации.

> Это редактор: готовый набор переводов и файлы War Thunder в репозиторий не входят.
> Для работы нужна установленная игра и созданная ею папка `lang`.

## Что умеет

- Искать по русскому и английскому тексту, а также идентификатору строки.
- Создавать несколько версий патча и копировать текущую версию в новую.
- Сохранять правки сразу после нажатия «Добавить в патч».
- Применять замены только к русской колонке CSV, сохраняя остальные поля.
- Сообщать, сколько замен применено, сколько ключей отсутствует и сколько
  исходных строк изменилось с момента создания правок.
- Экспортировать патч в JSON-файл и импортировать его в отдельный профиль.

## Быстрый старт из исходников

### 1. Подготовьте инструменты

Установите **[.NET SDK 10](https://dotnet.microsoft.com/download/dotnet/10.0)**
для своей ОС и архитектуры. Нужен именно SDK, одного Runtime недостаточно.
Подойдут терминал и любой редактор; IDE и дополнительные .NET workloads не требуются.

```sh
dotnet --version
```

Ожидается `10.0.xxx`. Файл `global.json` позволяет использовать установленный
стабильный SDK семейства 10.0 начиная с 10.0.100.

На Linux нужен графический сеанс X11 или XWayland. Для Debian/Ubuntu установите
системные библиотеки Avalonia:

```sh
sudo apt-get update
sudo apt-get install -y libx11-6 libice6 libsm6 libfontconfig1
```

Список ОС и библиотек: [документация Avalonia](https://docs.avaloniaui.net/docs/supported-platforms).

### 2. Скачайте код

```sh
git clone https://github.com/piksel-man231/wt-translator-local.git
cd wt-translator-local
```

Или выберите на GitHub **Code → Download ZIP**, распакуйте архив и откройте терминал
в папке, где лежит `WtTranslator.sln`.

### 3. Соберите и запустите

```sh
dotnet restore WtTranslator.sln
dotnet build WtTranslator.sln -c Release --no-restore
dotnet run --project src/WtTranslator.App -c Release --no-build
```

При первом восстановлении зависимостей нужен интернет для NuGet.
Дальнейшая работа приложения с локализацией происходит локально.

## Собрать приложение для распространения

Публикация с `--self-contained true` включает .NET Runtime: на компьютере получателя
устанавливать .NET не потребуется. Системные графические библиотеки Linux всё равно
нужны. Сохраняйте **всю папку публикации**, включая дополнительные файлы, если они есть.

### Windows x64

Запустите из корня репозитория в PowerShell или терминале:

```sh
dotnet publish src/WtTranslator.App -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true -p:IncludeNativeLibrariesForSelfExtract=true -o out/win-x64
```

Откройте `out/win-x64/WtTranslator.App.exe`. Для передачи приложения упакуйте
содержимое `out/win-x64` в ZIP. Сборка не имеет коммерческой цифровой подписи.

### macOS: пакет .app

Скрипт запускается **на Mac** и требует доступной команды `codesign`
(при необходимости установите Command Line Tools командой `xcode-select --install`).

Для Apple Silicon:

```sh
./scripts/package-macos.sh osx-arm64 1.1.0
open out/bundle-osx-arm64/WtTranslator.app
```

Для Intel:

```sh
./scripts/package-macos.sh osx-x64 1.1.0
```

Результат — `out/bundle-<архитектура>/WtTranslator.app` и архив
`dist/WtTranslator-1.1.0-<архитектура>.zip`. Переместите `.app` в «Программы».
Скрипт использует локальную ad-hoc подпись; приложение не нотарифицировано Apple.
Для скачанной сборки macOS может потребовать разрешить открытие в
«Системные настройки → Конфиденциальность и безопасность».

### Linux x64

```sh
dotnet publish src/WtTranslator.App -c Release -r linux-x64 --self-contained true -p:PublishSingleFile=true -p:IncludeNativeLibrariesForSelfExtract=true -o out/linux-x64
./out/linux-x64/WtTranslator.App
```

Если после переноса потерялось право запуска:

```sh
chmod +x out/linux-x64/WtTranslator.App
```

Для другой архитектуры выберите подходящий RID, например `linux-arm64` или
`win-arm64`. Эти дополнительные варианты не входят в матрицу CI.

### Автоматические сборки на GitHub

Workflow **Build and test** собирает проект и запускает тесты на Windows, Linux
и macOS, затем публикует самостоятельные пакеты для `win-x64`, `linux-x64`,
`osx-arm64` и `osx-x64` в **Actions → нужный запуск → Artifacts**.

Мейнтейнер может выпустить релиз тегом в формате `vX.Y.Z`:

```sh
git tag v1.1.0
git push origin v1.1.0
```

После успешного CI архивы автоматически попадут в
[GitHub Releases](https://github.com/piksel-man231/wt-translator-local/releases).
Для обычного запуска приложения публикация релиза не требуется.

## Подготовить War Thunder

1. Закройте игру и сохраните резервную копию `config.blk` и существующей `lang`,
   если вы уже меняли локализацию.
2. Включите пользовательскую локализацию в настройках игры и перезапустите игру.
   Если папка `lang` не появилась, закройте игру, откройте `config.blk` в папке
   установки и добавьте следующую строку **внутрь существующего блока `debug{ ... }`**:

   ```text
   testLocalization:b=yes
   ```

   Если строка уже есть со значением `no`, замените его на `yes`.
3. Запустите игру один раз: она создаст `lang` с файлами `*.csv` и `localization.blk`.
4. Закройте игру. В приложении выбирайте именно эту папку `lang`.
5. Для просмотра результатов выберите в игре **русский язык**.

Где искать папку установки: в Steam откройте управление игрой → свойства →
установленные файлы → обзор. Для другой установки используйте её фактический путь.
Приложение не ищет установку автоматически.

Официальные инструкции:
[War Thunder Wiki](https://wiki.warthunder.com/cdk/1819-a-better-guide-to-localization-mods),
[русская инструкция](https://wiki.warthunder.ru/cdk/creation_locale).

## Как пользоваться

### Внести первую правку

1. Запустите WT Translator Local.
2. Нажмите **«Обзор…»** и выберите созданную игрой папку `lang`.
   Внизу окна появится число загруженных строк.
3. Оставьте профиль `default` или создайте свой: введите имя версии и нажмите
   **«Создать версию»**. Допустимы 1–40 букв, цифр, символов `_` и `-`.
4. В поиске введите часть русского текста, английского текста или ключа.
   Поиск не учитывает регистр и показывает до 100 результатов. Пустой запрос
   оставляет список пустым; уточняйте запрос, если нужной строки не видно.
5. Выберите строку. В поле **«На что заменить»** введите свой текст.
6. Нажмите **«Добавить в патч»**. Правка сразу сохранится на диске в текущем профиле.
7. Нажмите **«Применить патч»**, чтобы записать переводы в файлы игры.
8. Запустите War Thunder с русским языком и проверьте результат.

Изменение текста в поле само по себе не сохраняется: обязательно нажмите
«Добавить в патч». Применение изменяет файлы `lang` на месте; выполняйте его при
закрытой игре. Автоматическая резервная копия файлов игры не создаётся.

### Несколько версий перевода

В выпадающем списке **«Версия патча»** выбирается активный локальный профиль.
При создании версии флажок **«копия текущей»** переносит в неё уже сохранённые правки.
Без флажка создаётся пустой патч. После создания версии профили редактируются отдельно.

Переключение профиля не отменяет замены, ранее записанные в игру. Чтобы полностью
сменить набор переводов, сначала восстановите чистую `lang`, затем примените нужный
профиль. Кнопка **«Обновить»** перечитывает список локальных профилей и файлы `lang`.

### Убрать замену или вернуть оригиналы

**«Убрать из патча»** удаляет выбранную правку из профиля, но не восстанавливает
уже изменённый CSV. Чтобы вернуть исходные тексты, восстановите резервную копию
либо дайте игре создать новую `lang`, затем примените оставшиеся правки.

Кнопка **«Удалить папку lang»** требует второго нажатия в течение четырёх секунд.
Удаляется вся выбранная папка, включая изменения других модов; встроенного отката
нет. Удаление разрешено только для папки с именем `lang` и файлом `localization.blk`.
При необходимости заранее скопируйте её в безопасное место.

### После обновления игры

1. Закройте игру и сделайте резервную копию текущей `lang`.
2. Удалите или перенесите старую `lang` из папки установки.
3. Запустите игру с включённой пользовательской локализацией, чтобы получить свежие
   файлы, затем снова закройте игру.
4. В редакторе нажмите **«Обновить»**, выберите профиль и **«Применить патч»**.
5. Проверьте отчёт внизу окна и результат в игре.

В отчёте **«Изменился оригинал в игре»** означает, что русский исходный текст
отличается от того, на котором создавалась правка. Ваш перевод всё равно
применяется. **«Не найдено ключей»** означает, что соответствующие строки или
CSV-файлы отсутствуют в новой локализации; такие замены пропускаются.
Автоматического обновления `lang` и фонового повторного применения нет.

## Где лежат настройки и патчи

Все данные находятся в каталоге `WtTranslator.Local` внутри системной папки
`Environment.SpecialFolder.ApplicationData`:

| ОС | Обычный путь |
| --- | --- |
| Windows | `%APPDATA%\WtTranslator.Local` |
| macOS | `~/Library/Application Support/WtTranslator.Local` |
| Linux | `$XDG_CONFIG_HOME/WtTranslator.Local` или `~/.config/WtTranslator.Local` |

```text
WtTranslator.Local/
├── settings.json          # путь к lang и выбранный профиль
└── profiles/
    ├── default/
    │   └── overlay.json   # сохранённые замены
    └── my-translation/
        └── overlay.json
```

`default/overlay.json` появляется после первого сохранения правки.
Путь к `lang` можно передать через переменную окружения `WT_LANG_DIR`; при запуске
она имеет приоритет над сохранённой настройкой.

### Экспортировать и импортировать патч

**Экспорт:** выберите нужную версию и нажмите **«Экспорт патча…»**.
В диалоге сохранения укажите имя и папку для JSON-файла. В файл попадут все
сохранённые правки активного профиля. Перед экспортом нажмите «Добавить в патч»,
если вы только что редактировали текст строки.

**Импорт:** нажмите **«Импорт патча…»** и выберите JSON-файл. Приложение проверит
его и создаст отдельный профиль с именем файла. Если имя уже занято, добавится
числовой суффикс. Новый профиль автоматически станет активным; существующие
профили сохранятся. Для записи переводов в игру нажмите **«Применить патч»**.

- Для экспорта и импорта папка игры не требуется; она нужна для применения.
- Файл содержит только замены и хэши исходных строк, без настроек и пути к игре.
- Поддерживаются также прежние файлы `profiles/<имя>/overlay.json`.
- Отмена диалога или некорректный файл оставляют текущий профиль без изменений.
- Импорт не объединяет патчи и не отменяет уже применённые в игре замены.

Чтобы передать перевод другому человеку, экспортируйте файл и отправьте его.
Получатель импортирует файл и применяет профиль к своей папке `lang`.

Для переноса из прежней версии WT Translator скопируйте нужные файлы
`WtTranslator/profiles/<имя>/overlay.json` в аналогичные папки `WtTranslator.Local`.
Старые настройки и служебные файлы переносить не требуется.

## Если что-то не работает

| Симптом | Что проверить |
| --- | --- |
| `dotnet` не найден | Установите SDK 10 и откройте новый терминал. |
| SDK не подходит | `dotnet --list-sdks` должен показывать 10.0.100 или новее в семействе 10.0. |
| Ошибка NuGet при сборке | Проверьте доступ к `https://api.nuget.org/v3/index.json` и повторите `dotnet restore`. |
| Папки `lang` нет | Включите пользовательскую локализацию и запустите игру один раз. |
| Загружено 0 строк | Выбрана именно `lang`, в ней есть CSV с колонками `<English>` и `<Russian>`? |
| Поиск пустой | Введите запрос: все строки сразу не показываются. |
| Правка не видна в игре | Нажмите «Добавить в патч», затем «Применить патч»; проверьте язык игры, путь к установке и перезапустите игру. |
| Ошибка доступа к файлам | Закройте игру, проверьте права записи на `lang` и папку данных. |
| Linux: окно не открывается | Проверьте графический сеанс и системные библиотеки из раздела запуска. |
| После смены профиля остались прежние тексты | Восстановите чистую `lang`, затем примените выбранный профиль. |

Если проблема сохраняется, создайте [Issue](https://github.com/piksel-man231/wt-translator-local/issues)
с ОС, версией приложения и шагами воспроизведения.

## Для разработчиков

```text
src/WtTranslator.App/        Avalonia: интерфейс, профили и настройки
src/WtTranslator.Core/       CSV-парсер, поиск, JSON-патчи и применение
tests/WtTranslator.Core.Tests/  xUnit-тесты ядра
packaging/macos/             шаблон Info.plist
scripts/                    упаковка macOS .app
.github/workflows/          проверка, сборки и релизы
```

```sh
dotnet build WtTranslator.sln -c Release
dotnet test WtTranslator.sln -c Release
```

Тесты покрывают CSV с кавычками и многострочными полями, точное восстановление
текстового формата, поиск, JSON и применение замен с отчётом о конфликтах.
Дополнительные проверки реальных файлов выполняются только при заданных
`WT_LANG_DIR` (папка с локализацией) и `WT_CLEAN_DIR` (её чистый вариант);
обычный прогон их не выполняет. Они используют ваши локальные данные и не
заменяют проверку результата в игре.
